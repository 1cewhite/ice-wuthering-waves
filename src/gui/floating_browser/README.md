# 悬浮浏览器使用说明

在游戏运行时把视频网页悬浮在最上层，用鼠标直接拖动、缩放，用全局快捷键控制播放。
适合一边挂机一边看攻略 / 直播。

## 功能一览

| 能力 | 说明 |
| --- | --- |
| 悬浮置顶 | 窗口始终显示在游戏窗口上方，且不出现在任务栏 |
| 鼠标拖动移动 | 按住悬浮窗顶部工具条的左侧区域直接拖动 |
| 鼠标拖动改大小 | 拖动悬浮窗的右边缘 / 下边缘 / 右下角，像普通 Windows 窗口一样 |
| 可调透明度 | 悬浮窗工具条上的滑块，20%–100% 实时生效 |
| 鼠标穿透 | 开启后点击直接落到下层窗口（游戏），悬浮窗变成纯显示 |
| 悬浮工具条 | 拖动、缩放、透明度、穿透、置顶、隐藏全部在悬浮窗自己身上操作 |
| 全局快捷键 | 游戏处于前台时依然生效（系统级热键） |
| 精确视频控制 | 直接操作网页 `<video>`，快进/后退精确到秒，倍速 0.25x–4.0x |

## 快速开始

1. 打开程序，在左侧导航栏找到 **悬浮浏览器** 标签页。
2. 在「播放源」中填入视频页面地址，或点击预设按钮（哔哩哔哩 / YouTube）。
3. 点击 **启动悬浮浏览器**。
4. 窗口出现后，**所有外观操作都在悬浮窗顶部的工具条上完成**。
5. 在悬浮窗内打开具体视频并开始播放，随后即可用快捷键控制。

## 悬浮窗工具条

窗口顶部有一条深色工具条（28px 高，浮在网页之上，不改变网页尺寸与布局）：

```
[ 拖动此处移动窗口 ................ ]  [====透明度====]  [穿透]  |  [📌] [—] [✕]
        ↑ 按住这里拖动整个窗口              ↑ 左右拖        ↑ 点击切换  图钉 横杠 红叉
```

| 元素 | 操作 |
| --- | --- |
| 左侧「拖动此处移动窗口」 | 按住并拖动 → 移动整个悬浮窗 |
| 左 / 右 / 下边缘 | 拖动 → 沿该方向改变窗口大小 |
| 四个角 | 拖动 → 同时改变宽高 |
| 透明度滑块 | 拖动 → 实时调整整窗不透明度 |
| **穿透** 按钮 | 点击 → 开启/关闭鼠标穿透，开启后按钮变蓝 |
| **弹幕** 按钮 | 点击 → 开关「把弹幕映射到游戏画面最上层」，开启时按钮变蓝；**右键 → 弹幕设置面板** |
| **字幕** 按钮 | 点击 → 开关「把字幕映射到游戏画面最上层」（与弹幕互不影响）；**右键 → 字幕设置面板** |
| **图钉** 按钮 | 点击 → 切换是否始终置顶，开启时按钮变蓝 |
| **横杠** 按钮 | 点击 → 收起悬浮窗（须用快捷键或「显示/隐藏」按钮再唤出） |
| **红叉** 按钮 | 点击 → 关闭悬浮浏览器（悬停变红） |

> 工具条高度由 `webview_process.py` 的 `TOOLBAR_HEIGHT` 一个常量控制
> （同时决定工具条高度和左右/上侧缩放把手的起点），想再调矮/调高改它即可。

> **鼠标穿透**：开启后鼠标点击会直接穿过悬浮窗落到下面的游戏窗口，
> 悬浮窗只负责显示。需要恢复时，用「切换穿透」快捷键一键关闭穿透即可
> （穿透时鼠标点不到悬浮窗，所以必须用快捷键，或在 ok 主界面点「显示/隐藏」）。

> **缩放把手在最外侧**：页面滚动条保留（收窄为 8px 半透明），右侧缩放把手加宽到
> 18~22px，因此滚动条只盖住把手最外侧一小段，把手主体仍贴着窗口边缘可抓取。

> **最小尺寸**：宽度不小于 240px、高度不小于 140px。上限 3840×2160。

## 默认快捷键

| 动作 | 默认按键 |
| --- | --- |
| 播放 / 暂停 | `Alt + S` |
| 快进 5 秒 | `Alt + D` |
| 后退 5 秒 | `Alt + A` |
| 按住 3 倍速播放 | 按住 `Alt + F` |
| 音量 +10% | `Alt + C` |
| 音量 -10% | `Alt + X` |
| 切换鼠标穿透 | 单个 `` ` `` 键 |
| 切换弹幕映射 | `Alt + M` |

> **按住 3 倍速**：按住 `Alt + F` 时以 3 倍速播放，松开自动恢复原倍速。
> 实现上用的是**低级键盘钩子**（`WH_KEYBOARD_LL`）而不是 `RegisterHotKey`，
> 因为后者只能在按下时触发一次、无法感知「松开」。钩子只是**旁听**按键，
> 不占用热键，所以即使 `Alt + F` 被别的软件注册了也能正常工作。
> 按住期间会持续锁定 3 倍速，因此 B 站这类会在切集/跳转时把倍速重置回 1.0
> 的播放器也不会「按住没反应」。

> **热键冲突**：全局热键是系统级独占资源，被其它软件占用时注册会失败。
> 常见占用方：微信（`Alt+A` 截图）、QQ / WeGame / 网易 GameViewer 等游戏覆盖层、
> 录屏工具（AMD 录屏、网易云音乐）、游戏语音（Oopz）。注册失败时程序会在
> 「悬浮浏览器」页弹出提示并列出被占用的组合，改用其它组合即可
> （实测 `Ctrl + Shift + 字母` 通常空闲）。

## 自定义快捷键

在标签页的「全局快捷键」区域修改后，点击 **保存设置**，
再点击 **立即重载热键**（或重启悬浮浏览器）即可生效。

- 写法示例：`ctrl+shift+space`、`alt+f8`、`ctrl+alt+m`
- 支持的修饰键：`ctrl` / `alt` / `shift` / `win`
- 留空或填 `none` 表示不启用该动作
- 具体按键名可查阅 `src/gui/floating_browser/hotkeys.py` 中的 `_KEY_CODES`

如果某个热键被其它软件占用，启动时会弹出提示，换一个组合即可。

## 配置项说明

配置页（全局配置中的 *Floating Browser* / *Floating Browser Hotkey*）也可直接编辑：

| 键 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `url` | 字符串 | `https://www.bilibili.com/` | 启动时加载的地址 |
| `width` / `height` | 整数 | `560` / `340` | **上次使用**的窗口尺寸，由鼠标拖动自动写回 |
| `opacity` | 浮点 | `0.9` | 上次使用的不透明度，由工具条滑块写回 |
| `on_top` | 布尔 | `true` | 是否始终置顶 |
| `click_through` | 布尔 | `false` | 是否开启鼠标穿透 |
| `seek_step` | 数值 | `5` | 快进 / 后退的秒数 |
| `hover_opacity` | 浮点 | `0.3` | 穿透模式下鼠标悬停在窗内时降到的不透明度（配置页可调，5%–100%） |
| `log_output` | 布尔 | `false` | **日志总开关**：控制悬浮浏览器在主程序控制台 / 日志文件里的全部输出（见下） |
| `mirror_danmaku` | 布尔 | `false` | 启动时**弹幕**映射是否默认开启（平时用悬浮窗工具条上的弹幕按钮开关） |
| `mirror_subtitle` | 布尔 | `false` | 启动时**字幕**映射是否默认开启（平时用悬浮窗工具条上的字幕按钮开关） |

> `width` / `height` / `opacity` / `click_through` 不是「输入项」，
> 而是程序在每次点「保存设置」时把悬浮窗的实际状态记录下来，
> 下次启动直接沿用。要改它们，直接拖动悬浮窗即可。
> `hover_opacity` 可在 ok 主界面的「启动与窗口操作」卡片里直接调整并即时生效。

### 弹幕 / 字幕映射到最上层（`mirror_danmaku` / `mirror_subtitle`）

开启后，视频里的**弹幕和字幕会被搬到一块始终置顶的透明覆盖层上**，覆盖层
**铺满「游戏画面」**（= 游戏窗口客户区）—— 于是可以把悬浮窗隐藏、穿透或者
直接拖到别的屏幕，弹幕依然留在游戏画面上。

- **开关在悬浮窗工具条上**（ok 界面里没有这个开关）：
  - **弹幕按钮**（气泡图标）—— 单独开关弹幕；
  - **字幕按钮**（CC 图标）—— 单独开关字幕；
  - 两者互不影响，开哪个画哪个；都关掉时覆盖层隐藏。**默认都是关的**。
  - 热键 `Alt + M` 是「总开关」：同时开/关这两个。
- 覆盖层位置 = 游戏窗口客户区，游戏窗口被移动 / 改分辨率时每 0.5 秒重算一次；
  游戏没开时退回「跟随悬浮窗」。
- 覆盖层是**点击穿透**的，完全不挡游戏鼠标；也不会出现在任务栏、不抢焦点。
- 注意两点：
  1. **独占全屏（exclusive fullscreen）的游戏会盖住它**，请把游戏设成
     「无边框窗口 / 窗口化」；普通窗口化与无边框都没问题。
  2. **字幕需要先在播放器里打开 CC**（B 站播放器右下角字幕按钮）——
     字幕没有可用的接口（见下），只能从页面里取。

#### 弹幕数据从哪来：两条路径

| 路径 | 什么时候用 | 内容与位置从哪来 |
| --- | --- | --- |
| **自绘**（主路径） | 能拿到 `cid`，并且成功拉到弹幕 | 子进程**自己拉 B 站弹幕数据**，位置由**本地引擎按播放时刻算出来** |
| **DOM 映射**（回退） | 拿不到 `cid`、拉取失败（番剧要登录 / 被风控 / 非视频页…） | 读页面里弹幕元素的坐标再照搬 |

页面在这个链路里只做一件事：**每 200ms 上报一次「播到第几秒 / 哪个视频」**
（`aid` / `cid` / `bvid` / `p` / `currentTime` / `playbackRate` / `paused`）。
弹幕内容一律不走页面。切换是自动的，`inspect_mirror` 的 `source` 字段能看到当前走的哪条。

#### 自绘路径

**为什么值得换**：DOM 映射本质是在抄上游的渲染结果，于是被上游卡住 ——
页面 60ms 才更新一次坐标（要自己估速度、外推补帧，见下）、只能抄到「当前可见的
那几条」、seek / 倍速会让外推飘掉。自己拉数据自己算就没这些事：位置是 `t` 的函数，
seek / 暂停 / 倍速天然正确，一条弹幕都不会漏。

**数据来源**（`bilibili_danmaku.py`，2026-09-29 实测）：

| 通道 | 结果 |
| --- | --- |
| `x/v2/dm/web/seg.so`（protobuf，**主通道**） | 每段 360 秒、最多约 6000 条，**不需要 cookie**。实测一个 1410 条的视频一次拿全、平均 439ms。超出视频范围的段返回 **HTTP 304 + 空 body**（这就是停止条件） |
| `comment.bilibili.com/<cid>.xml`（回退） | 结构简单但**有硬上限**（反复实测都稳定截断在 1200 条），只在 protobuf 失败时兜底 |
| `x/player/v2` → `subtitle_url`（字幕） | ❌ **未登录拿不到**（实测 12 个热门视频的字幕轨全是 0 条）。所以字幕只能继续走 DOM 采集 |

protobuf 是按 wire format **手解**的（`parse_segment`），没引入 protobuf 依赖；
解析对截断/非法字节是容错的（解析到哪儿算哪儿，不抛异常）。

**运动参数**（`danmaku_engine.py`，都是在真实 B 站播放器上采样出来的）：

- **滚动弹幕是固定时长穿屏，约 7.1 秒** —— 这点最容易搞错：它**不是**固定速度。
  实测短弹幕 103px/s、长弹幕 117px/s，但 `(播放器宽 + 文本宽) / 速度` 都约 7.1s。
  按固定速度实现会在长弹幕上明显偏慢。
- 行高 ≈ 字号 × 1.2（20px 字号 → 24px 行距，实测行间距中位数 24px）。
- 播放器显示字号 = 弹幕自带的 `size` × 0.8（标准档 25 → 20px，小档 18 → 14.4px）。
- 顶部 / 底部弹幕停留 4 秒。

**行分配（避让）**：每条弹幕进来时挑一行，要求该行没被固定弹幕占着、且和该行
上一条滚动弹幕不会追尾。这里有个细节：宽度大的弹幕速度也大（固定时长），所以
光是「上一条是否已完全进入」**不够** —— 还要检查两条弹幕**同时存在**的整个区间内
间距都不为负（间距是时间的线性函数，取两个端点判断即可）。
找不到行就丢弃该条（和 B 站播放器一样，宁可少一条也不叠在一起）。

**字号与位置**：字号取弹幕自带的 `size`（不随覆盖层缩放），位置铺满整个覆盖层
（= 游戏画面）。所以画面比视频窗口大时，行距会显得比视频里宽 —— 画面放大了，
字没有放大。

#### DOM 映射路径（回退）

拉不到弹幕数据时自动走这条路，行为跟以前一致：

- 弹幕/字幕的**位置**按 `覆盖层尺寸 ÷ 页面视口尺寸` 映射进去；
- **字体除了位置以外其他样式都不变**：字号、字体、字重、描边、颜色一律用站点里的原值；
- 样式**取自站点的计算样式**（实测 B 站是 `font-family: SimHei…` /
  `font-weight: 700` / `text-shadow: rgb(0,0,0) 0 0 1px`）；
- **字幕按真实文字居中绘制**：页面里字幕容器是整宽的、文字居中，直接用容器矩形会画偏，
  所以页面侧用 `Range` 量出**文字本身**的矩形，GDI 侧再按文字中心对齐；
- **只镜像「真的在视口里」的元素**：播放器里存在一些存在于 DOM 但画在视口外的
  弹幕/字幕容器（实测有 y=501 而视口只有 361 高的字幕节点），不过滤就会出现
  「位置不对」——那些其实是被画到了屏幕外。

#### 设置面板（右键工具条按钮）

在悬浮窗工具条上**右键**「弹幕」或「字幕」按钮就会弹出设置面板（样式与选项对齐
B 站播放器的弹幕设置）。改完即时生效，并且**记在页面 localStorage 里** —— 下次
开镜像会自动套上，不用重设。

**弹幕设置**（字段与默认值对齐 B 站 `bpx_player_profile.dmSetting`）：

| 项 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| 按类型过滤 | 滚动 / 固定 | 都不屏蔽 | **选中 = 屏蔽**（与 B 站一致），对应 B 站的 `typeScroll` / `typeTopBottom` |
| 显示区域 | 10~100% | 100% | 占画面高度的比例，决定能排几行 |
| 不透明度 | 5~100% | 100% | 走分层窗口的 alpha 通道（`LWA_COLORKEY \| LWA_ALPHA`），不需要逐像素合成 |
| 弹幕字号 | 50~150% | 80% | 就是 B 站的 `fontsize`；实测 80% 时 25 档字号显示为 20px |
| 弹幕速度 | 5 档 | 适中 | 改的是滚动弹幕的**穿屏时长**（越快时长越短） |

> 「显示区域」「不透明度」的默认放宽到 100% 是为了保持原来「铺满且不透明」的观感；
> B 站默认是 50% / 70%，想要一样的效果在面板里调回去即可。

**字幕设置**（B 站网页版的字幕只有开关和语言选择，这三项参考 App 补的）：

| 项 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| 字幕大小 | 50~200% | 100% | |
| 字幕位置 | 0~100% | 88% | 垂直位置，0 = 贴顶、100 = 贴底 |
| 字幕背景不透明度 | 0~100% | 0% | 0% 时只画文字（带黑描边） |

**字幕为什么要单独一层**（`subtitle_overlay.py`）：

弹幕层用「颜色键」抠图，而**颜色键只有「全透明 / 全不透明」两种状态**，
做不了半透明背景。所以字幕另开一个窗口走真正的 per-pixel alpha：Pillow 渲染成 RGBA
（Pillow 能直接吐 `BGRA` 字节，不用换通道）→ 写进 32bpp DIB（`biHeight` 取负 = top-down）
→ `UpdateLayeredWindow(..., ULW_ALPHA)`。窗口只包住字幕那一块（几十 KB），而且字幕内容
变化很慢，实测单次渲染 2~4ms，不构成负担。

副作用（好的那种）：字幕不再经过弹幕层，所以弹幕层的「不透明度」只影响弹幕，
字幕有自己的一套设置，两边互不干扰。

游戏窗口是**怎么认出来的**（`webview_process._find_game_hwnd`）：

- 优先用 ok 框架给的句柄（`device_manager.hwnd_window.hwnd`，每秒钟同步一次）；
- 主进程没给 / 拿不到时，子进程自己按 **窗口类名 `UnrealWindow` + 进程 exe
  `Client-Win64-Shipping.exe`** 搜（与 `config.py` 的 `windows` 段一致）。
- ⚠️ **只看类名是不够的**：所有虚幻引擎游戏的窗口类名都是 `UnrealWindow`，
  实测本机同时开着另一个 UE 游戏（Abiotic Factor）时会被认错。所以必须再核对
  进程 exe 名 —— 这道校验有回归测试守着。

**开销**（实测 1600×900、26 条弹幕）：单帧绘制 ~7ms，按 60fps 全速重画时约占单核 40%。
开销主要跟「覆盖层面积 + 弹幕条数」有关；没有滚动弹幕（或映射关闭）时覆盖层降到
12ms 慢轮询，基本不占 CPU。自绘路径每帧都重算一次（不缓存帧），量级相同。

**DOM 回退路径怎么补到 60fps**（`danmaku_overlay.py`，三段都踩过坑）：
1. **速度估算**在子进程侧：缓存每条弹幕（按节点 id + 文字）上一次的 x，差分出速度，
  再一阶低通压掉取整抖动；播放器池化复用节点时会换文字，所以必须一起校验文字。
2. **本地外推**：覆盖层在两次推送之间按 `x + vx*dt` 重画，最多外推 150ms
   （页面暂停/卡住时画面就冻结，不会让弹幕一直飘出去）。
3. **帧节奏**：Windows 上 `Event.wait(13ms)` 实际会多睡一截，且默认计时器粒度
   约 15.6ms —— 结果是稳稳掉到 43~55fps。改成「按绝对时刻对齐 + 预扣多睡的部分」，
   并在覆盖层线程里 `timeBeginPeriod(1)`（停止时还原），才稳在 60fps。
   另外 `SetWindowPos` 只在几何变化时才调（每帧调会强制窗口管理器重新合成）。

**自绘路径不需要上面这些**：位置是算出来的，每帧取到的都是那一刻的正确值，
没有采样间隔、也没有外推近似。

实现要点（详见 `danmaku_overlay.py`）：

- B 站弹幕/字幕都是 **DOM 元素**（`.bili-danmaku-x-dm` /
  `.bili-subtitle-x-subtitle-panel-*`，实测不是 canvas），主页面里每 60ms 读一次
  `getBoundingClientRect()` 就能拿到「这一刻的动画位置」，连滚动过程都能 1:1 复刻。
- 播放器会把弹幕节点**池化复用**，不可见的那些 `opacity` 是 0，必须过滤，
  否则会有一堆东西堆在视频左上角。
- 覆盖层**没有用 WebView2**：实测 `pywebview` 的 `transparent=True` 在这里无效
  （它给窗体设的透明键管不到 WebView2 子窗口自己的像素，窗口化模式下 WebView2
  依然不透明合成）。改用一个 Win32 分层窗口 + **纯黑**颜色键抠图 + GDI 画字
  （先描近黑描边再画本体）。颜色键用纯黑而不是品红：颜色键做不了半透明，
  文字抗锯齿边缘是「描边色 ↔ 颜色键」的混合，黑键混出来还是黑（看不见），
  品红键会在每个字外面留一圈紫边（用户实测反馈过）；代价是描边色得用近黑 (10,10,10)。
- 离屏位图按尺寸缓存复用（铺满 2K/4K 时每帧重建一张十几 MB 的位图太浪费）。
- 缩放与字体都下沉到覆盖层：页面只报「视口坐标 + 站点样式」，`set_viewport` /
  `set_style` 决定怎么画 —— 这样游戏窗口改尺寸时不需要重新注入页面脚本。
- 窗口**创建时就要带 `WS_EX_TOPMOST`**：实测在已显示的窗口上再调用
  `SetWindowPos(HWND_TOPMOST)` 反而会把置顶位弄丢。

### 日志总开关（`log_output`）

悬浮浏览器（含它的子进程、启动器、全局热键、配置页）往**控制台 / 日志文件**写的
内容**全部**由这一个开关控制，默认**关闭**：

- 打开方式：ok 主界面 →「悬浮浏览器」→「启动与窗口操作」卡片里的
  **「输出悬浮浏览器日志」**勾选框（改完即时生效，不用重启），
  或直接把配置里的 `log_output` 改成 `true`。
- 关掉后，控制台与 `logs/` 里不会出现任何来自悬浮浏览器的行
  （包括子进程的 `@@TRACE@@` / `@@LAUNCHER@@` 诊断信息）。
- **界面上的提示不受影响**：启动失败、热键被占用、子进程报错这类关键信息
  仍会以弹窗 / 状态栏文字告知，所以平时关着日志也不会「出问题却毫无提示」。
- 实现：所有输出统一走 `src/gui/floating_browser/log.py`；子进程通过启动配置里的
  `verbose` 字段拿到同一个开关值。

## 工作原理

```
Qt 主进程
 ├─ FloatingBrowserTab        配置界面（网址 / 启停 / 热键 / 状态）
 ├─ FloatingBrowserService    单例服务，串起窗口与热键
 ├─ HotkeyManager             RegisterHotKey + PeekMessage 轮询
 └─ multiprocessing.Process ──► webview_process.py（子进程）
                                 ├─ pywebview + Edge WebView2 窗口
                                 ├─ Win32：去边框 / 置顶 / 分层透明度 / 鼠标穿透
                                 ├─ 注入 HTML 工具条（拖动 / 缩放 / 穿透 / 透明度）
                                 └─ evaluate_js 注入脚本操作 <video>
```

`pywebview.start()` 会阻塞且必须在主线程运行，无法与 Qt 事件循环共存，
因此窗口被放进独立子进程，主进程通过队列双向通信。

### 拖动与缩放是怎么实现的

窗口是无边框的（`frameless=True`），所以标题栏和边框拖拽都不存在。实现方式：

1. 向页面注入一段 HTML，在顶部生成工具条与 7 个透明缩放把手（左/右/下边 + 四角）；
2. 把手上的 `mousedown` 记录起始屏幕坐标，`mousemove` 时通过
   `pywebview` 的 JS 桥把 `screenX/screenY` 发给 Python；
3. Python 侧（`_handle_drag_action`）用 `SetWindowPos` 实时搬运/改尺寸，
   松手时把最终几何回传主进程并写入配置。

指针一旦离开工具条下沿，会立即通知 Python 放宽点击区域，
避免出现「窗口下半部分点不动」的问题。

> **滚动条与把手的取舍**：WebView2 的滚动条是原生层，会盖住 `right:0` 的 DOM 把手。
> 所以保留滚动条时，必须把右侧把手**加宽**（18~22px），让滚动条（8px）只盖住其最外侧，
> 把手主体仍露在窗口边缘可抓取。

### 三个容易踩的坑（改动前请先读）

拖动 / 缩放 / 穿透全部依赖同一个前提：**子进程必须拿到窗口 HWND**。
以下三点任何一个出问题，三个功能会同时失效，而且不报错、只表现为「没反应」。

1. **HWND 类型** — pywebview 在 Windows 上返回的是 pythonnet 的 `IntPtr`，
   不是 `int`。早期代码写 `isinstance(handle, int)` 判断，导致句柄永远解析为 0，
   所有 Win32 调用静默跳过。现在统一走 `_coerce_handle()` 做类型归一。

2. **`drag_start` 不能被节流合并** — 鼠标拖动为了性能用
   `requestAnimationFrame` 合并 `mousemove`。但 `drag_start` 若被合并掉，
   Python 侧取不到起始矩形，后续所有 `drag_move` 都成空操作。
   现在只有 `drag_move` 参与节流，`drag_start` / `drag_end` 立即发送。

3. **注入脚本必须异步** — `about:blank` 等页面上 `evaluate_js` 会长时间不返回。
   若在初始化流程里同步注入，会永久卡住初始化，轮询线程永远起不来，
   几何/状态再也回传不到主进程。现在 `_install_scripts` 放独立线程，
   且 `_evaluate()` 自带超时保护。

> 另外：`_poll_geometry` 首次拿到真实矩形必须上报（不能只在值变化时上报），
> 否则主进程会一直停留在 `(-1, -1)` 占位值。

## 常见问题

**没有出现悬浮窗，只是打开了浏览器？**
系统缺少 Edge WebView2 运行时。Win11 与多数 Win10 已内置；
如缺失，可安装 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。
未安装时会自动降级为「系统浏览器打开视频页面」，此时快捷键不可用。

**窗口拖不动 / 拉不动大小？**
请按住工具条上标有「拖动此处移动窗口」的区域；缩放把手贴窗口最外侧边缘（约 8~22px 宽），
鼠标移到窗口边缘即可抓取。若开启了「鼠标穿透」，先按 `Ctrl+Shift+H` 关闭穿透再操作。

**鼠标点不到悬浮窗了？**
多半是开启了「鼠标穿透」（按钮会变蓝）。按 `Ctrl+Shift+H` 关闭穿透即可
（穿透时鼠标会穿过悬浮窗，只能靠快捷键或 ok 主界面的「显示/隐藏」按钮恢复）。

**快捷键没反应？**
先确认悬浮窗处于运行状态（标签页显示「运行状态」）。
若启动时提示热键被占用，请在「全局快捷键」区域改用其它组合。

**视频无法识别 / 控制无效？**
部分站点（如带 DRM 的付费内容）限制脚本访问视频元素。
此外请在悬浮窗内让视频真正开始播放后再使用快捷键。

**关闭程序后还有 `msedgewebview2.exe` 残留？**
程序已在退出时递归结束子进程树（`taskkill /F /T`）。
若 Edge 浏览器本身正在运行，它自己的 WebView2 进程属正常现象。

## 多语言（i18n）

界面文案跟着**主程序的语言**走，支持仓库里已有的 5 个语言：
`zh_CN` / `zh_TW` / `ja_JP` / `ko_KR` / `es_ES`（`i18n/<locale>/LC_MESSAGES/ok.po|.mo`）。

文案分两类，走的是同一条 gettext 链路：

| 类别 | 例子 | 怎么翻 |
| --- | --- | --- |
| **ok 原生界面** | 配置页的「视频网址」「启动悬浮浏览器」「全局快捷键」 | 代码里直接写英文 msgid（`self.tr("Video URL")`），gettext 查表 |
| **注入页面的文案** | 工具条按钮 tooltip、拖动提示、设置面板全部标签 | 登记在 `i18n.py` 的 `PAGE_TEXT`（key → 英文），主进程翻译好后随启动配置传进子进程 |

**为什么页面文案要绕这一圈**：工具条和设置面板是注入到网页里的 HTML/JS，跑在 WebView2
**子进程**里，而 `og.app.tr`（gettext 入口）在主进程。所以流程是：

```
tab.py / hotkeys.py ──self.tr（英文 msgid）────────────► gettext ──► ok.po/.mo
i18n.PAGE_TEXT ──page_texts()（主进程翻译）──► 启动配置 ──► 子进程注入 window.__okI18N
                                                              └─► JS 里 T('panel.area') 取值
```

好处是**翻译仍然只维护在 .po 文件里**，JS 里不再另搞一份语言表；而且英文原文就是 msgid，
和项目其它模块一致。JS 侧 `T(key)` 拿不到表时会退回 key 本身，最坏情况是显示成 key 而不是崩掉。

**加一条新文案的步骤**：

1. ok 界面 → 直接在代码里写英文 `self.tr("...")`；
   页面 → 在 `i18n.py` 的 `PAGE_TEXT` 里登记 key，JS 里用 `T('key')`。
2. 给 5 个语言的 `ok.po` 补条目（msgid = 英文原文），空 `msgstr` 会被 gettext 当成"未翻译"退回英文。
3. **编译 mo**：`polib` 的 `po.save_as_mofile()`（或 ok 的 `convert_to_mo_files()`）。
   ⚠️ 只改 `.po` 不编译 `.mo` 是不生效的 —— 运行时装的是 `.mo`。

**容易踩的坑**：

- **不同语义别共用同一个英文 msgid**。比如状态栏的「倍速」和设置面板的「弹幕速度」
  一开始都译成了 `Speed`，结果两边显示同一条译文（已改成 `Playback speed` / `Speed`）。
- 加条目时**别覆盖已有译文**（别人可能已经翻好了），只在 `msgstr` 为空时补。
- 日志与注释**不进翻译表**（ok-script 的约定：只翻 GUI 可见文案）。
